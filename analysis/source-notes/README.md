# source-notes/

Historical artifacts from Ven about the personal-assistant system he's been wanting.

## What lives here

Notes, diary entries, voice-memo transcripts, screenshots, frustration-logs about current tools, "if I could just have..." statements — anything pre-dating the chat-mode session of 2026-05-11 that captures what Ven has been thinking about a system like coo4one.

These are the highest-fidelity calibration input for the synthesis. The five research lanes answer *what is possible*; the user-journey sketch is COO speculation about *what the experience could be*; these notes are the closest thing to *what Ven actually wants*.

## How to use this folder

Drop files in whatever format they exist in. No reformatting required:

- Markdown — preferred but not required.
- Plain text — fine.
- PDFs — fine.
- Screenshots of handwritten notes — fine.
- Photos — fine.
- Voice-memo transcripts — fine; raw is fine.
- Exports from Heptabase / Apple Notes / Things — fine.

Naming convention: anything readable. Date-prefix if known (`2024-11_dream-system.md`), descriptive otherwise (`heptabase-ipad-frustrations.md`). The COO will read and index.

## What the COO does with them

At synthesis time:
1. Reads each file.
2. Extracts: stated wants, stated frustrations, named tools / features, design preferences, anti-features (things Ven explicitly doesn't want).
3. Reconciles against the research lanes (what's possible) and the user-journey sketch (COO speculation).
4. Surfaces mismatches: "you said you wanted X; research says X is hard because Y; here are the trade-offs."
5. Cites the source notes inline in the synthesis where they ground decisions.

The notes are durable — kept in the repo for future reference, not consumed and discarded.
